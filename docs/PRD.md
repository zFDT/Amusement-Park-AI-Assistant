# 游园助理 - 产品需求文档 (PRD)

**版本**: v1.0  
**日期**: 2026-05-18  
**状态**: 草稿

---

## 一、产品概述

### 1.1 产品背景

上海迪士尼乐园和香港迪士尼乐园是国内最受欢迎的主题乐园，但长时间排队是游客最大的痛点。现有的官方 App 仅提供排队时间查询，缺乏智能路线规划能力。本产品旨在通过 AI 大模型整合实时排队数据、用户偏好和乐园地图，为游客提供个性化的游园路线推荐，最大化游园体验。

### 1.2 产品定位

面向计划游览迪士尼乐园的个人/家庭用户，提供 **AI 驱动的对话式游园规划助理**，核心价值：
- 减少无效排队时间
- 根据人员构成和偏好个性化规划
- 游园中实时动态调整路线

### 1.3 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---------|------|---------|
| 家庭游客 | 带小孩/老人，体力有限 | 合理安排体力，不遗漏亲子项目 |
| 年轻情侣/朋友 | 追求刺激项目，时间充裕 | 高效刷完热门项目，减少等待 |
| 迪士尼粉丝 | 有明确目标项目，熟悉园区 | 精准规划，不错过限定活动 |
| 首次游客 | 对园区不熟悉 | 全面体验，不知道从哪开始 |

## 二、可行性分析

### 2.1 技术可行性

#### ✅ 可行项

| 模块 | 方案 | 可行性 |
|------|------|--------|
| 实时排队数据 | queue-times.com 提供免费 API，覆盖上海/香港迪士尼 | 高 |
| AI 路线推荐 | Claude / GPT-4 API，支持复杂多因素推理 | 高 |
| 对话式交互 | SSE 流式输出，前端 Chat UI | 高 |
| 地图展示 | 使用乐园官方公开地图图片 + SVG 标注层 | 中高 |
| 用户位置 | 浏览器 Geolocation API（园内 GPS 精度有限，辅以手动选点） | 中 |

#### ⚠️ 风险项

| 风险 | 描述 | 缓解方案 |
|------|------|---------|
| 排队数据准确性 | queue-times.com 数据有 5-15 分钟延迟，非官方 | 标注数据来源和更新时间，允许用户手动修正 |
| 迪士尼 ToS | 直接爬取官方 App 数据违反服务条款 | 使用合规第三方 API，不直接爬取 |
| LLM 成本 | 高并发下 API 调用成本较高 | 对相似请求做缓存，非核心场景降级到规则引擎 |
| 地图版权 | 使用官方地图图片需注意版权 | 使用公开的 OpenStreetMap 数据或自绘 SVG 地图 |

### 2.2 商业可行性

- 国内迪士尼年客流量超 1000 万，目标用户基数大
- 现有竞品（大众点评攻略、小红书）均为静态内容，无实时 AI 规划
- MVP 阶段可免费运营，后期通过景区合作/会员订阅变现
- 技术壁垒：实时数据 + AI 推理的组合，复制成本较高

### 2.3 结论

**整体可行性：高**。核心技术路径清晰，最大风险是实时数据质量，通过用户手动修正机制可以有效缓解。建议先做上海迪士尼的 MVP 验证，再扩展到香港迪士尼和其他乐园。

## 三、功能需求

### 3.1 功能模块总览

```
游园助理
├── 游前规划模块
│   ├── 乐园选择
│   ├── 游园信息录入（日期/时间/人员/偏好）
│   └── 初始路线生成
├── 对话助理模块（核心）
│   ├── 自然语言交互
│   ├── 路线推荐与解释
│   └── 实时调整建议
├── 实时数据模块
│   ├── 排队时间展示
│   ├── 项目开放状态
│   └── 数据刷新机制
├── 地图模块
│   ├── 园区地图展示
│   ├── 当前位置标注
│   └── 推荐路线可视化
└── 会话管理模块
    ├── 多用户隔离
    └── 会话历史保存
```

### 3.2 核心功能详细需求

#### F1 - 游前规划（游园信息录入）

**触发场景**：用户首次进入或点击"重新规划"

**输入项**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 目标乐园 | 单选 | 是 | 上海迪士尼 / 香港迪士尼 |
| 游园日期 | 日期选择 | 是 | 用于判断是否节假日/周末 |
| 入园时间 | 时间选择 | 是 | 建议开园前 30 分钟到达 |
| 离园时间 | 时间选择 | 是 | 用于计算可用时长 |
| 人员构成 | 多选标签 | 是 | 成人/儿童(年龄)/老人/孕妇/轮椅 |
| 人数 | 数字 | 是 | 影响餐饮/设施推荐 |
| 兴趣偏好 | 多选标签 | 否 | 刺激项目/亲子项目/表演/拍照打卡/美食 |
| 必玩项目 | 多选（从项目列表） | 否 | 用户指定必须体验的项目 |
| 体力评估 | 滑块(1-5) | 否 | 影响步行距离和项目密度 |
| 过往经历 | 单选 | 否 | 首次/去过1-2次/多次 |
| 特殊需求 | 文本 | 否 | 自由输入，如"孩子怕黑不能进暗室项目" |

**输出**：生成初始游园计划，进入对话界面

---

#### F2 - 对话式 AI 助理（核心功能）

**交互模式**：Chat 界面，支持流式输出

**AI 能力要求**：

1. **初始规划**：根据 F1 输入 + 当前实时排队数据，生成按时间排序的游园路线，包含：
   - 每个项目的建议到达时间
   - 预计排队时间
   - 步行路线说明
   - 餐饮/休息时间安排

2. **动态调整**：用户在游园中随时对话调整，支持：
   - "我现在在幻想世界，下一个去哪？"
   - "雷鸣山漂流关闭了，帮我重新规划"
   - "孩子累了，推荐附近可以休息的地方"
   - "我想提前离园，还有 2 小时，最值得玩什么？"

3. **信息查询**：
   - "XX 项目现在排多久？"
   - "哪个餐厅适合带孩子？"
   - "花车巡游几点开始？"

**系统 Prompt 设计原则**：
- 注入当前实时排队数据（JSON 格式）
- 注入用户偏好和人员构成
- 注入当前时间和用户位置（如有）
- 要求 AI 输出结构化路线时使用固定格式，便于前端解析渲染

---

#### F3 - 实时数据展示

**排队时间面板**：
- 按区域分组展示所有项目排队时间
- 颜色编码：绿(<30min) / 黄(30-60min) / 红(>60min) / 灰(关闭)
- 显示最后更新时间
- 支持手动刷新

**数据来源优先级**：
1. queue-times.com API（主要来源，5-15 分钟延迟）
2. 用户手动上报（实时，但覆盖有限）
3. 历史均值（兜底，当 API 不可用时）

**刷新策略**：每 5 分钟自动刷新一次，用户可手动触发

---

#### F4 - 地图模块

**展示内容**：
- 园区地图（SVG 矢量图，支持缩放）
- 各项目位置标注（含实时排队时间气泡）
- 当前推荐路线高亮
- 用户当前位置（GPS 或手动选点）

**交互**：
- 点击项目标注查看详情
- 点击地图选择当前位置
- 路线在地图上可视化展示

---

#### F5 - 会话管理

- 每个用户生成唯一 Session ID（存储在 localStorage）
- 服务端按 Session ID 隔离对话历史和用户状态
- 会话有效期：24 小时（覆盖一天游园）
- 支持"重新开始规划"清空当前会话

---

### 3.3 非功能需求

| 指标 | 要求 |
|------|------|
| 响应时间 | AI 首字符响应 < 2s（流式输出） |
| 并发支持 | MVP 阶段支持 50 并发用户 |
| 可用性 | 99% uptime（排除第三方 API 故障） |
| 移动端适配 | 响应式设计，优先移动端体验 |
| 数据安全 | 不存储用户个人身份信息，Session 匿名化 |

## 四、用户旅程

### 4.1 游前规划旅程

```
用户打开网站
    → 选择乐园（上海/香港迪士尼）
    → 填写游园信息（引导式表单，约 2 分钟）
    → AI 生成初始路线（流式输出，约 10-20 秒）
    → 查看路线 + 地图可视化
    → 可继续对话调整
```

### 4.2 游园中调整旅程

```
用户在园内打开网站（已有会话）
    → 直接进入对话界面
    → 输入当前位置（GPS 或手动）
    → 告知变化情况（项目关闭/体力不支等）
    → AI 实时重新规划
    → 查看更新后的路线
```

## 五、数据模型

### 5.1 核心实体

**Park（乐园）**
```
id, name, location, timezone, opening_hours, map_image_url
```

**Attraction（项目）**
```
id, park_id, name, category, description, 
min_height, duration_minutes, 
coordinates(lat, lng), area_name,
is_lightning_lane, age_restriction
```

**WaitTime（排队时间）**
```
attraction_id, wait_minutes, status(open/closed/down),
last_updated, source(api/user_report)
```

**Session（用户会话）**
```
session_id, park_id, visit_date, entry_time, exit_time,
party_composition, preferences, must_do_attractions,
created_at, expires_at
```

**Message（对话消息）**
```
id, session_id, role(user/assistant), content, 
created_at, context_snapshot(JSON)
```
